================================================================================
                    BILLING API ENDPOINTS SUMMARY
================================================================================

PROJECT: TRC Platform Spring Boot Backend (Java 21)
LOCATION: /api and /api/v1/admin/billing/periods
AUTHENTICATION: Bearer JWT tokens (User or Admin roles)
COST MODEL: 50 cents per API request

================================================================================
                        USER-FACING ENDPOINTS
================================================================================

Path: /api/billing/current
Method: GET
Auth: User (Bearer Token)
Purpose: Get current billing period for authenticated user
Status: 200 OK
Response: CurrentBillingResponse
  - id (UUID)
  - isCurrent (Boolean) - always true
  - periodStart (Date) - 1st of month
  - periodEnd (Date) - last of month
  - periodLabel (String) - "January 2025"
  - paymentStatus (String) - pending/paid/overdue/waived
  - totalRequests (Integer) - API calls this month
  - totalCostCents (Integer) - requests * 50 cents

Behavior:
  * Auto-creates period if doesn't exist
  * Monthly periods: 1st to last day
  * Real-time cost calculation

================================================================================

Path: /api/billing/periods
Method: GET
Auth: User (Bearer Token)
Purpose: List all billing periods (up to 100 most recent)
Status: 200 OK
Response: {"results": [BillingPeriodResponse, ...]}
  - Each period includes:
    * id, periodLabel, periodStart, periodEnd
    * totalRequests, totalCostCents
    * isCurrent, paymentStatus
    * paidAt, paidAmountCents, paymentReference

Behavior:
  * Ordered by periodStart DESC (newest first)
  * Includes current and historical periods
  * Wrapped in "results" object

================================================================================

Path: /api/billing/periods/{periodId}
Method: GET
Auth: User (Bearer Token)
Parameters: periodId (UUID) - billing period to retrieve
Purpose: Get detailed billing period with all API requests
Status: 200 OK / 404 Not Found / 403 Forbidden
Response: BillingPeriodDetailDto
  - id, periodStart, periodEnd
  - totalRequests, totalCostCents
  - paymentStatus, current
  - requests[] array with:
    * id, status, durationMs, flowId, result

Behavior:
  * Only returns if period belongs to user
  * All requests ordered by timestamp DESC
  * Perfect for invoice generation

================================================================================

Path: /api/usage/summary
Method: GET
Auth: User (Bearer Token)
Purpose: Quick usage statistics
Status: 200 OK
Response: UsageSummaryResponse
  - today (Integer)
  - yesterday (Integer)
  - last7Days (Integer)
  - thisMonth (Integer)
  - lastRequestAt (String) - ISO timestamp

Behavior:
  * Real-time from request logs
  * Perfect for dashboard widgets
  * Null lastRequestAt if no requests

================================================================================
                        ADMIN ENDPOINTS
================================================================================

Path: /api/v1/admin/billing/periods
Method: GET
Auth: Admin (Bearer Token + ADMIN role)
Query Parameters:
  - userId (UUID, optional)
  - status (String, optional) - pending/paid/overdue/waived
  - page (int, default: 0)
  - size (int, default: 20)
Purpose: List all billing periods with filtering
Status: 200 OK / 403 Forbidden
Response: Page<BillingPeriodAdminResponse>
  - Paginated results with metadata

Status: STUB - Returns null (filtering not implemented yet)

================================================================================

Path: /api/v1/admin/billing/periods/{periodId}/mark-paid
Method: POST
Auth: Admin (Bearer Token + ADMIN role)
Parameters: periodId (UUID)
Purpose: Record payment received for a billing period
Request Body: MarkPaidRequest
  {
    "paidAmountCents": 4500,           // required, >= 0
    "paymentReference": "TXN-2025-001", // required, max 255 chars
    "paymentDate": "2025-01-15T14:30:00.000000Z", // optional, defaults to now
    "notes": "Paid via credit card"   // optional
  }

Status: 200 OK / 400 Bad Request / 403 Forbidden / 404 Not Found
Response: BillingPeriodAdminResponse

Updates Made:
  * paymentStatus → "paid"
  * paidAt → paymentDate (or now if not provided)
  * paidAmountCents → amount paid
  * paymentReference → transaction reference
  * notes → appends if provided

Validation:
  * paidAmountCents must be >= 0
  * paymentReference required, not blank, max 255 chars
  * paymentDate must be valid ISO timestamp

================================================================================

Path: /api/v1/admin/billing/periods/{periodId}/mark-overdue
Method: POST
Auth: Admin (Bearer Token + ADMIN role)
Parameters: periodId (UUID)
Purpose: Mark billing period as overdue (unpaid past due date)
Request Body: MarkOverdueRequest
  {
    "notes": "Invoice sent, no payment after 30 days" // optional
  }

Status: 200 OK / 403 Forbidden / 404 Not Found
Response: BillingPeriodAdminResponse

Updates Made:
  * paymentStatus → "overdue"
  * paidAt → now
  * paidAmountCents → NOT updated (stays null)
  * paymentReference → NOT updated (stays null)
  * notes → appends if provided

Usage:
  * Track accounts unpaid past due date
  * Trigger collection notices
  * Can transition to "paid" if late payment received

================================================================================

Path: /api/v1/admin/billing/periods/{periodId}/mark-waived
Method: POST
Auth: Admin (Bearer Token + ADMIN role)
Parameters: periodId (UUID)
Purpose: Mark billing period as waived/forgiven
Request Body: MarkWaivedRequest
  {
    "notes": "Waived due to service outage" // optional
  }

Status: 200 OK / 403 Forbidden / 404 Not Found
Response: BillingPeriodAdminResponse

Updates Made:
  * paymentStatus → "waived"
  * paidAt → now
  * paidAmountCents → NOT updated (stays null)
  * paymentReference → NOT updated (stays null)
  * notes → appends if provided

Usage:
  * Forgive charges for credits/promotions
  * Handle service outage compensation
  * Waive fees for new customers
  * Final state (no further payment expected)

================================================================================
                    PAYMENT STATUS FLOW DIAGRAM
================================================================================

                    PENDING (default state)
                        |
            |-----------|-----------|
            |           |           |
            v           v           v
          PAID      OVERDUE      WAIVED
          (Final)   (Tracking)   (Final)
            |
            |-- mark-paid
            |-- mark-overdue
            |-- mark-waived

         OVERDUE
            |
            |-- mark-paid (late payment)
            |-- mark-waived (waive late charge)

Key Points:
  * pending → paid: Normal payment flow
  * pending → overdue: Invoice unpaid past due
  * pending → waived: Credit/forgiveness
  * overdue → paid: Late payment received
  * overdue → waived: Late charges forgiven
  * paid → (final state, no transitions)
  * waived → (final state, no transitions)

================================================================================
                        KEY BUSINESS RULES
================================================================================

1. BILLING PERIODS
   - One period per calendar month (1st to last day)
   - Automatic creation when needed
   - Monthly assignment based on Berlin timezone
   - Only ONE marked as current = true per user

2. COST CALCULATION
   - 50 cents per API request
   - Automatic: totalCost = totalRequests * 50 cents
   - Updated when requests are added

3. USER ISOLATION
   - Users can only view their own periods
   - Only admins can view/manage all periods
   - Access control via Spring Security

4. REQUEST LOGGING
   - Every API call creates RequestLog
   - Automatically associated with current period
   - Updates total request count
   - Recalculates costs

5. ADMIN OPERATIONS
   - Only admins can change payment status
   - Only admins can add notes
   - All changes are audited (paidAt timestamp)
   - Atomic transactions with @Transactional

================================================================================
                    DATABASE SCHEMA SUMMARY
================================================================================

TABLE: billing_periods
  Columns:
    - id (UUID, PK)
    - user_id (UUID, FK) → users
    - period_start (Date) - 1st of month
    - period_end (Date) - last of month
    - total_requests (Integer) - request count
    - total_cost_cents (Integer) - calculated cost
    - is_current (Boolean) - active flag
    - payment_status (Enum) - pending/paid/overdue/waived
    - paid_at (Timestamp) - when paid/processed
    - paid_amount_cents (Integer) - amount paid
    - payment_reference (Varchar 255) - transaction ID
    - notes (Text) - admin notes
    - version (Bigint) - optimistic lock

  Indexes:
    - idx_user_period (user_id, period_start)
    - idx_current_period (is_current)

TABLE: request_logs
  Columns:
    - id (UUID, PK)
    - user_id (UUID, FK) → users
    - billing_period_id (UUID, FK) → billing_periods
    - request_ts (Timestamp)
    - status (Varchar)
    - duration_ms (Integer)
    - flow_id (Varchar)
    - result (Text)

================================================================================
                    QUICK TROUBLESHOOTING
================================================================================

Error: 404 Period not found
  → Verify period exists and belongs to authenticated user
  → Check period UUID format

Error: 400 Payment reference is required
  → paymentReference is mandatory for mark-paid
  → Must be non-blank, max 255 characters

Error: 403 Access denied
  → Non-admin trying admin endpoint
  → User trying to access another user's period
  → Check ADMIN role assignment

Error: 400 Paid amount must be non-negative
  → paidAmountCents must be >= 0
  → Cannot have negative amounts

No requests showing
  → Check if requests were actually made
  → Verify request logs are being created
  → Check billing period dates match request timestamps
